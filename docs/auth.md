# Аутентификация

Скрипты не принимают токен аргументом и не читают файлы ключей. `yc` сам берёт
учётные данные из профиля. Так токен не попадает в `ps`, в JSON-конверт и в
историю команд.

Проверенные переменные окружения CLI 1.41.0, которые можно задать снаружи:
`YC_TOKEN`, `YC_IAM_TOKEN`, `YC_PROFILE`, `YC_CLOUD_ID`, `YC_FOLDER_ID`.
Раннер прокидывает в argv только `YC_PROFILE` как `--profile`. Остальное `yc`
читает сам.

## Как войти

Официальные способы, от более предпочтительного:

1. Пользователь или федерация: `yc init` на машине с браузером.
2. Имперсонация сервисного аккаунта. У пользователя должна быть роль
   `iam.serviceAccounts.tokenCreator` на этот аккаунт. Раннер принимает
   идентификатор флагом `--impersonate-service-account-id`. Это id, не секрет.
3. Авторизованный ключ в профиле: `yc config set service-account-key ./key.json`.
   Файл ключа не коммитится. В `.gitignore` уже есть `key.json` и `sa-key.json`.
4. Сервисный аккаунт виртуальной машины: `yc config set instance-service-account true`.
   Отдельный ключ не нужен.

Для чтения метаданных обычно хватает роли `viewer` на каталог или облако.
Отдельные сервисы смотрят свою роль (`k8s.viewer`, `lockbox.viewer` и другие).
Команда без прав не останавливает обход: ошибка пишется в конверт этого ресурса.

Не запускайте `yc config list` в скриптах сбора. Команда печатает OAuth-токен и
закрытый ключ профиля. Её нет в каталоге инвентаризации.

Подробности: [аутентификация сервисным аккаунтом](https://yandex.cloud/en/docs/cli/operations/authentication/service-account).
