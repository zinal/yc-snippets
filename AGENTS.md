# Инструкции для агентов

Репозиторий `yc-snippets` хранит скрипты Yandex Cloud. Основная работа — сбор
метаданных уже созданных ресурсов и аккуратные операции над ними.

## Куда смотреть

- Команды `list` бери из `src/yc_snippets/data/inventory.json`. Это снимок `yc --help`, а не список по памяти.
- Смысл полей каталога и формат конверта — в `docs/inventory.md`.
- Официальные документы, SDK и сервисы без команды `list` — в `docs/public-sources.md`.
- Аутентификация — в `docs/auth.md`.
- Перед сценарием сбора прочитай скилл `yc-inventory`. Перед скриптом, который создаёт или удаляет ресурсы, — `yc-automation`. Если нужно свериться с документацией или обновить каталог — `yc-public-sources`.

## Как писать код

- Новая выборка ресурсов — это запись каталога и тест, а не отдельная строка в shell, собранная наугад.
- Изменяющие скрипты клади в `scripts/automation/`. У них есть `--dry-run`. Пока пользователь явно не просит выполнить изменение, останавливайся на сухом прогоне.
- Общие флаги и запрет секретов в argv уже реализованы в `yc_snippets.plan.build_argv`. Не обходи эту функцию.
- Идентификаторы облака, каталога и ресурса — параметры. Не вписывай чужие id в код.
- Ответ `yc --format json` для `list` — массив. Неизвестный сервис не выдумывай: посмотри `yc <группа> --help` или proto в `yandex-cloud/cloudapi`.
- Если команде нужен id родителя (`scope=parent`), сначала собери родителя, потом запускай дочернюю команду с его флагом.

## Секреты

Не читай и не сохраняй OAuth-токены, IAM-токены, авторизованные ключи, payload Lockbox, пароли и закрытые ключи. `yc config list` для этого не используй. В репозиторий не клади `key.json` и вывод инвентаризации из `out/`.

## Проверка

`python -m pytest` не требует учётных данных. Живой обход облака запускай только когда профиль `yc` уже настроен, и сначала покажи `--dry-run`.
